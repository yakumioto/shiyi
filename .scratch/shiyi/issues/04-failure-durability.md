# 04: 失败与持久化边界

**What to build:** 当模型不可用、输入非法、文件损坏或配置改变分片粒度时，用户得到明确结果，记录不会被静默污染或丢失。模型失败时本次输入不保存；崩溃留下的半行被隔离；中间损坏让服务拒绝启动而不是装作正常。

**Blocked by:** 02 (查询路径).

**Status:** ready-for-agent

- [x] 模型不可达、超时或返回非法分类/回答时返回 503，数据目录不新增行。
- [x] 空内容返回 400；超过请求体上限返回 413；启用 Bearer 后缺失或错误 token 返回 401。
- [x] 模拟最后一行不完整：服务启动成功，坏尾被移动到隔离位置，之前的记录仍可读。
- [x] 模拟中间行损坏：服务启动失败，错误信息指出位置，不静默丢数据。
- [x] 分片配置为按月、按周、按天时，记录进入对应分片，跨边界行为正确。
- [x] 存储失败与检索失败分别返回 500 的明确错误码，不泄露模型原始错误。
- [x] 测试覆盖上述路径，可在无网络环境运行。

## Comments

已完成。集成在 `feat/shiyi-v1`。

- 模型不可达/超时 → 503 `model_unavailable`；模型输出非法 → 502 `model_invalid_response`；两种情况都不写文件。
- 空内容 → 400；超过 body 上限 → 413；Bearer 缺失/错误 → 401；`/healthz` 不鉴权。
- 半行 → 移到 `corrupt/<分片>.<纳秒>.tail` 并截断；中间损坏 → 启动失败并指出文件与行号。
- 分片：monthly/weekly/daily，全部按 UTC；跨月边界有专门测试。
- 存储失败 → 500 `storage_failed`；检索失败 → 500 `search_failed`；错误信息不含密钥与原文。
- 验证：存储缝直接测恢复与分片边界；HTTP 缝测全部错误码；无网络。
