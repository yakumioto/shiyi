# Shiyi v1

Status: ready-for-agent → **implemented**（集成分支 `feat/shiyi-v1`，8 张票全部关闭）

## Problem Statement

我在聊天里随手记下的事实、计划和偏好，散落在不同对话里；笔记软件要求我先分类、整理、维护结构；通用助手又会忘记，或者把我的话改写成它自己的版本。我需要一个只做两件事的个人记忆：把我说的话原样记下来，之后能用自然语言问出来，并且答案能指回原话。

它必须足够轻：单用户、本地文件、不引入数据库和向量检索；我能直接看到数据、直接备份。它也必须足够诚实：没有依据时就说没找到，不猜、不编造、不把查询或闲聊混进记忆。

## Solution

Shiyi 是一个单用户、Chat-first 的本地服务。每次输入先由可配置的 LLM 判定为记录、查询或无法识别；只有记录会以原文追加到按月分片的 JSONL，记录时间同时作为唯一标识和引用锚点。

查询时，LLM 通过 `search_memory` 在记录中做字面检索，按需多轮读取后生成带引用的回答；没有证据就返回「没有找到相关记忆」，回答不落盘。CLI 和极简 Web 共用同一个 HTTP 入口。模型不可用时服务直接不可用，不猜测分类，也不降级成假的回答。

## User Stories

1. 作为个人记忆用户，我希望用自然语言直接说一句话就能保存，以便不必先决定分类、标签或文件位置。
2. 作为个人记忆用户，我希望只有我真正想记住的内容才进入记忆，以便闲聊和提问不会污染记录库。
3. 作为个人记忆用户，我希望系统逐字保留我的原话，以便记录不会被摘要、改写或补全。
4. 作为个人记忆用户，我希望用自然语言提问就能从记录中得到回答，以便不必自己写 grep 或翻文件。
5. 作为个人记忆用户，我希望每个回答都列出它使用了哪些记录，以便我能核对回答是否有依据。
6. 作为个人记忆用户，我希望没有相关记录时系统明确说「没有找到」，以便我不会把模型的常识当成我的记忆。
7. 作为个人记忆用户，我希望一条输入同时包含记录和提问时整体按提问处理，以便系统不会只保存半句话。
8. 作为个人记忆用户，我希望系统无法判断用途时明确告诉我，以便我知道这条没有被保存。
9. 作为个人记忆用户，我希望每条记录都有精确到纳秒的时间，以便我能区分先后并把它作为引用依据。
10. 作为个人记忆用户，我希望系统在我不小心重发时保留两条独立记录，以便它不会静默合并我的内容。
11. 作为个人记忆用户，我希望记录按月分文件，以便单个文件不会无限增长。
12. 作为个人记忆用户，我希望分片粒度可以配置为按月、按周或按天，以便我按自己的记录频率选择。
13. 作为个人记忆用户，我希望确认成功的记录在进程崩溃后仍然存在，以便我不丢失已经写入的内容。
14. 作为个人记忆用户，我希望崩溃留下的半行被隔离而不是静默丢弃，以便我知道发生了什么。
15. 作为个人记忆用户，我希望模型不可用时收到明确错误，以便我知道这次没有保存、需要重试。
16. 作为个人记忆用户，我希望模型失败时这次输入不被保存，以便系统不会把一条未分类的内容塞进记忆。
17. 作为个人记忆用户，我希望重试时重新发送原文即可，以便我不需要理解内部状态。
18. 作为个人记忆用户，我希望单次查询有检索次数、记录数量和时间上限，以便服务不会因为一次复杂提问而挂住。
19. 作为个人记忆用户，我希望预算耗尽时看到部分回答和明确状态，以便我知道答案可能不完整。
20. 作为个人记忆用户，我希望互相矛盾的记录并列返回，以便系统不会替我选择一个「正确」版本。
21. 作为个人记忆用户，我希望记录不可修改，以便今天的引用不会因为以后的编辑而改变含义。
22. 作为个人记忆用户，我希望通过 CLI 一次性记录或提问，以便我能把它接进脚本和快捷键。
23. 作为个人记忆用户，我希望有一个交互式 CLI，以便我可以连续记录和提问。
24. 作为个人记忆用户，我希望有一个极简 Web 页面，以便我在浏览器或手机上使用。
25. 作为个人记忆用户，我希望 Web 页面安全地显示模型输出，以便回答中的脚本不会被执行。
26. 作为个人记忆用户，我希望查询和回答不被保存，以便我的提问不会成为新的记忆或历史档案。
27. 作为个人记忆用户，我希望每次查询都是自包含的，以便结果不依赖之前的对话状态。
28. 作为个人记忆用户，我希望系统支持中文和中英混合内容的字面检索，以便我用日常语言记录也能查到。
29. 作为个人记忆用户，我希望检索结果能解释为「哪个词命中了哪段原文」，以便我能理解为什么某条记录被引用。
30. 作为个人记忆用户，我希望每个回答标明状态（正常、预算耗尽、无结果），以便我知道该不该继续追问。
31. 作为个人记忆用户，我希望引用里直接带上被引用记录的原文，以便我不需要再发一次请求才能看到依据。
32. 作为个人记忆用户，我希望系统拒绝引用本次检索没有返回过的记录，以便回答不能凭空指向不存在的依据。
33. 作为个人记忆用户，我希望单条输入有大小上限，以便一次超长粘贴不会拖垮服务。
34. 作为个人记忆用户，我希望服务返回明确的错误码，以便客户端能区分「输入错了」「模型不可用」「引用非法」。
35. 作为个人记忆用户，我希望数据就是普通 JSONL 文件，以便我能用任何工具查看、复制和备份。
36. 作为自部署者，我希望用配置文件选择模型提供商、地址和模型名，以便我在 DeepSeek、OpenAI 或其他兼容服务之间切换。
37. 作为自部署者，我希望 API key 只从环境变量读取，以便密钥不会写进配置、日志或仓库。
38. 作为自部署者，我希望可以启用 Bearer token，以便把服务暴露到局域网时不是完全敞开。
39. 作为自部署者，我希望有健康检查端点，以便容器和监控能判断进程是否存活。
40. 作为自部署者，我希望用容器运行并挂载数据卷，以便升级镜像时记录不丢。
41. 作为维护者，我希望冻结测试集覆盖分类、检索、引用和失败路径，以便修改提示词或代码时能发现回归。
42. 作为维护者，我希望 CI 使用假模型而不是真实 API，以便测试稳定、免费、不需要密钥。
43. 作为维护者，我希望真实模型评测独立于 CI，以便观察分类质量而不让随机波动阻塞发布。
44. 作为维护者，我希望启动时校验配置、数据目录和 ripgrep，以便部署问题在启动时暴露而不是在第一次请求时。
45. 作为维护者，我希望日志不包含密钥和完整原文，以便排障时不会泄露个人数据。

## Implementation Decisions

- **产品形态**：单用户、本地优先的 HTTP 服务；一个入口 `POST /messages`；CLI 与极简 Web 都只是客户端。不做多用户、账号体系或多副本。
- **意图判定**：所有输入都交给可配置的 LLM，判定为记录、查询或无法识别；混合输入整体判为查询；不保留规则分类。分类只看当前输入，不看历史。
- **落盘时机**：先分类，后落盘。只有记录会写文件；查询、回答和无法识别都不写文件。这是对原始「所有输入先持久化」的有意放弃，见 ADR-0004、ADR-0005、ADR-0006。
- **记录模型**：每条记录只有三个字段：`version`（v1 恒为 1）、`content`（逐字原文）、`time`（服务端生成的 UTC RFC3339Nano 时间）。`time` 严格递增、唯一，同时是记录标识和引用锚点。没有 `id`、没有 `kind`、没有附件。
- **存储**：append-only JSONL，按月分片（可配置为按周或按天），按 UTC 切分；写入后 `fsync` 再返回成功；首次创建文件时同步目录。没有数据库、没有索引、没有派生视图。
- **崩溃恢复**：启动时扫描分片；最后一行不完整则移动到隔离目录并截断到最后一个换行符；中间行损坏则启动失败并指出位置，不静默丢数据。
- **检索**：唯一工具 `search_memory(keywords, limit)`；任一关键词大小写不敏感地作为子串出现在 `content` 中即命中；用 ripgrep 预筛文件，再用 Go 解析 JSONL 精确判断；按 `time` 降序返回。跨换行短语不保证命中，这是 JSONL 转义的已知限制。
- **回答**：LLM 多轮调用 `search_memory`，最终输出 `{answer, citations}`；每个引用必须是本次查询实际返回过的 `time`，否则返回非法引用错误。没有任何结果时返回固定「没有找到相关记忆」，丢弃模型文本，防止凭常识作答。引用校验只能保证「引用存在」，不能保证「每句话都被引用支撑」，这是 LLM 生成回答的已知限制。
- **预算**：默认最多 3 次检索调用、20 条不同记录、回答阶段 30 秒、单请求 60 秒；均可配置。预算耗尽时做一次不带工具的「立即回答」调用，状态为 `budget_exhausted`。
- **回答不落盘**：没有查询历史、回答档案或审计日志；重启后不保留任何会话状态。见 ADR-0006。
- **无更正与遗忘**：记录不可变；矛盾记录并列返回，系统不做真值仲裁。见 ADR-0003。
- **API 契约**：`POST /messages` 接收 `{"content":"..."}`；成功返回记录（201）、查询回答（200）或无法识别（200）；错误统一为 `{"error":{"code","message"}}`。错误码覆盖输入非法、未授权、请求过大、存储失败、检索失败、引用非法、模型输出非法、模型不可用。只额外提供 `GET /healthz`；不提供按时间取记录、历史回答或会话接口。
- **鉴权**：默认只监听本机；可选 Bearer token，由配置指向的环境变量提供；`/healthz` 不鉴权。
- **模型配置**：TOML 配置；分类与回答可分别配置 OpenAI-compatible 的 base URL、模型名、密钥环境变量、超时和温度；密钥只从环境变量读取，不写配置、不写日志。
- **提示词**：分类提示词与回答提示词作为带版本号的常量维护；提示词变更视为行为变更，必须通过冻结测试集。
- **客户端**：CLI 支持一次性发送、交互式 REPL 与启动服务；Web 是单页输入框加消息列表，只调用同一 HTTP 入口，不做多会话、历史、设置页。
- **部署**：单二进制；容器镜像必须包含 ripgrep；数据卷挂载；容器内默认监听 `0.0.0.0:8787`，本地默认 `127.0.0.1:8787`。

## Testing Decisions

- **好测试的标准**：只验证外部可观察行为，不绑定内部函数、字段顺序或实现结构；测试必须确定性、无网络、可并行、失败信息能直接指出哪条行为坏了。表驱动测试优先。
- **测试缝**：已与用户确认三个缝。
  1. **HTTP 入口**（最高缝）：注入假 LLM，使用真实存储与真实 ripgrep，在临时数据目录上通过 `POST /messages` 验证分类、落盘、查询、引用、状态码、鉴权与错误路径。CLI 与 Web 复用此缝，不单独开缝。
  2. **记录存储**：直接验证时间严格递增、按月/周/日分片、写入后的持久化、半行恢复与中间损坏失败。理由是这些行为无法通过 HTTP 稳定触发，属于持久化层的外部契约。
  3. **LLM HTTP 边界**：用 `httptest` 验证 OpenAI-compatible 请求形状、工具调用解析、超时、非 2xx、坏 JSON 与密钥不出现在错误里。理由是与外部提供商的协议适配需要独立验证。
- **测试模块**：HTTP 层、存储层、LLM 适配层、检索层、回答编排层；CLI 的端到端行为复用 HTTP 缝，输出格式化只做纯函数单测；Web 只做手工冒烟，不做浏览器自动化。
- **冻结测试集**：版本化目录，包含分类与查询夹具、每个文件的 SHA-256 清单；测试用假 LLM 按夹具逐轮返回，真实存储与真实 ripgrep；测试不得访问网络。冻结版本一旦发布不得就地修改，新增用例进入新版本目录，测试跑全部版本。CI 不调用真实模型；真实模型评测脚本独立运行，不阻断发布。
- **既有先例**：仓库目前没有测试先例；采用 Go 标准库的 `testing`、`httptest`、`t.TempDir`，加真实 `rg` 作为外部依赖。测试启动时检查 `rg` 是否存在，缺失时给出明确失败信息。
- **门禁**：`go test ./... -race`、`go vet ./...`、冻结集全部通过。集成测试不得访问外网。

## Out of Scope

- 多用户、账号、租户隔离、权限模型。
- 记录更正、删除、遗忘、墓碑与冲突仲裁。
- 查询历史、回答持久化、审计日志、会话恢复。
- 对话上下文与多轮追问；每次查询必须自包含。
- 异步任务、队列、幂等键、重试、去重与断点续跑。
- 附件、图片、PDF、音频、OCR、视觉模型。
- 向量检索、embedding、数据库、全文索引、标签、实体抽取、事实抽取。
- AI 摘要或任何生成内容作为证据。
- 记录编辑、版本递增与合并。
- Web 多会话、历史浏览、设置页、登录页、Markdown 渲染、流式输出。
- 多设备同步、云备份、数据迁移、加密。
- 非文本输入、语音输入、提醒、通知。
- 模型微调、提示词自动优化、A/B 测试平台。

## Further Notes

- **有意偏离原始规格**：本 spec 放弃了原始需求中的「所有输入先持久化」「回答及来源持久化」「异步处理」「幂等写入」「混合输入按片段收录」。这些不是遗漏，理由见 ADR-0004、ADR-0005、ADR-0006；实现与文档不得把它们描述成已实现。
- **已知风险**：LLM 可能把查询误判为记录，而系统没有更正功能，错误记录会永久留下；网络抖动重发可能产生重复记录；跨换行短语检索不到；引用校验只能保证引用来源存在，不能保证回答的每句话都被支撑；数据是明文 JSONL，没有加密；模型不可用即服务不可用。
- **技术细节**：数据字段、配置项、提示词、错误码表、分片与恢复规则、验收清单见 [design.md](design.md)。
- **实施任务**：按 [issues/](issues/) 中 01 到 10 的顺序执行；01 为项目骨架，02 为存储，03 为 LLM 客户端，04 为检索，05 为回答循环，06 为 HTTP API，07 为 CLI，08 为 Web，09 为冻结测试集，10 为容器与文档。
