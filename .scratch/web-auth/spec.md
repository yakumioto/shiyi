# Web 安全登录与 CLI 客户端移除

Status: ready-for-agent

本规格依据 2026-11-05 的需求讨论与领域澄清。测试接缝已获用户确认；本状态表示可交付实施，不表示功能已经实现。本规格只覆盖当前交付，其他 README 边界的已定方向保存在 Further Notes，不能据此扩大本次验收范围。

## Problem Statement

我希望在手机和电脑上通过公网 HTTPS 使用自己的私人记忆系统，并且允许记录敏感原文。目前开启 Bearer 鉴权后，Web 没有登录入口，也不会携带凭据，因而无法提交；不开鉴权则可能让他人读取或写入记忆，漏配鉴权还可能静默退回匿名访问。

CLI 只是早期验证工具，不是我的真实使用入口，继续维护它和单独的 API token 会增加配置及安全负担。我需要的是单用户、多设备、可过期和撤销的 Web 登录：平时重启不丢登录，设备丢失时能收回访问，忘记密码时能从服务器恢复。

现有文档把“登录会话”与“对话上下文”混在一起，并将模型业务不可用描述为整个服务不可用。安全边界也需要说清楚：我信任服务器及管理员，当前版本允许原文发送给配置的模型网关及其上游模型，但不能把登录保护宣传为数据加密或防止模型提供方接触原文。

## Solution

提供应用内的单用户密码登录，以浏览器登录会话保护记忆业务；用户自己管理反向代理与 HTTPS。无用户名、注册、邮箱找回和第三方账号系统，登录密码与模型 API key 分离。

部署时提供密码哈希，正常模式下配置缺失或无效就拒绝启动。登录后可在多个浏览器使用；登录会话连续 7 天未使用过期，最长有效期为登录后 30 天，正常服务重启保持有效。用户可退出当前设备，重新验证密码后退出所有设备，或通过替换服务器上的密码哈希并重启来恢复访问及作废旧登录会话。

移除面向用户的 CLI 客户端和旧 Bearer 认证方式，但保留服务启动入口、Web 所需 HTTP 接口及容器启动能力。原文存储、分类、检索、引用和即时回答的业务语义不因登录改变；查询、回答与对话上下文仍不持久化。

本次同步更新使用文档、部署说明和检查，准确区分应用已实现的安全措施、部署者需要完成的措施及当前仍保留的产品边界。

## User Stories

1. 作为私人记忆系统的唯一使用者，我希望在 Web 输入密码登录，以便无需 CLI 就能安全使用服务。
2. 作为使用者，我希望不需要用户名或注册流程，以便单用户部署保持简单。
3. 作为使用者，我希望未登录者不能调用记忆业务，以便他人不能读取、推断或写入我的记忆。
4. 作为使用者，我希望登录密码与模型 API key 分离，以便两类凭据各司其职。
5. 作为部署者，我希望只配置密码哈希而非持久保存明文登录密码，以便减少凭据暴露。
6. 作为部署者，我希望有可复现的安全哈希生成步骤，以便不必自行研究或实现密码算法。
7. 作为部署者，我希望缺失、空白或无效的登录配置导致明确启动失败，以便服务不因漏配而匿名开放。
8. 作为开发者，我希望只有显式选择开发匿名模式才允许无登录运行，以便测试便利不成为生产默认。
9. 作为升级者，我希望旧 Bearer 配置得到明确迁移错误，以便不会误以为旧 token 仍在保护服务。
10. 作为使用者，我希望同一密码可在自己的多台设备建立独立登录会话，以便手机和电脑都可使用。
11. 作为使用者，我希望关闭再打开浏览器后仍可保持有效登录，以便无需每次重新输入密码。
12. 作为使用者，我希望正常服务重启不使有效登录会话失效，以便日常维护不打断使用。
13. 作为使用者，我希望连续 7 天未使用的登录会话过期，以便闲置设备不会无限保有访问资格。
14. 作为使用者，我希望登录后最长 30 天必须重新验证密码，以便频繁访问也不能无限延长同一次登录。
15. 作为使用者，我希望会话过期后能看到明确的登录提示，以便知道提交失败是因为认证而不是模型故障。
16. 作为使用者，我希望同一页面中未成功提交的原文在重新登录前后得以保留，以便不因认证过期丢失输入。
17. 作为使用者，我希望重新登录不会自动重发原文，以便不意外产生重复记录。
18. 作为使用者，我希望能退出当前设备而不影响其他设备，以便按需结束访问。
19. 作为使用者，我希望再次验证密码后能退出所有设备，以便设备丢失时及时回收访问。
20. 作为使用者，我希望注销和过期在服务端真正生效，以便复制旧 Cookie 也无法继续访问。
21. 作为忘记密码的使用者，我希望通过服务器设置新密码哈希并重启恢复访问，以便不依赖邮箱或短信。
22. 作为使用者，我希望密码哈希变更后全部旧登录会话失效，以便旧凭据不能继续授权访问。
23. 作为使用者，我希望模型网关故障时仍可登录和注销，以便故障不阻碍安全操作。
24. 作为使用者，我希望其他网站不能借用我的登录状态写入记忆或执行认证操作，以便避免跨站请求伪造。
25. 作为使用者，我希望登录接口限制猜密码的尝试，以便公网暴露不等于允许无限暴力尝试。
26. 作为使用者，我希望他人不能通过触发永久锁定让我无法登录，以便限速不会变成简单的拒绝服务手段。
27. 作为使用者，我希望网页脚本无法直接读取登录凭据，以便缩小凭据泄露风险。
28. 作为使用者，我希望退出后页面清除已展示的私人原文和回答，以便设备交给他人时不残留当前界面的私人信息。
29. 作为使用者，我希望登录会话不成为记忆条目或回答证据，以便认证状态不污染记忆库。
30. 作为使用者，我希望刷新页面后不恢复历史查询和回答，以便登录不悄悄引入聊天存档。
31. 作为使用者，我希望敏感原文仍可作为记录保存，以便安全设计不以禁止记录私人信息为代价。
32. 作为使用者，我希望文档明确原文可以发送给模型网关及上游模型，以便理解外发边界而不是误认为数据完全留在本地。
33. 作为使用者，我希望模型失败时不绕过分类写入原文，以便查询和无法识别的输入不被错误赋予证据资格。
34. 作为使用者，我希望模型失败时页面保留未成功提交的原文，以便我可主动重试。
35. 作为部署者，我希望日志不包含密码、Cookie、模型密钥或记忆原文，以便故障排查不产生另一份秘密存档。
36. 作为部署者，我希望认证状态与记忆数据分开管理，以便明确权限、恢复和撤销边界。
37. 作为部署者，我希望文档说明 JSONL 仍是明文，以及加密磁盘和加密备份各自保护什么，以便不把登录等同于静态加密。
38. 作为部署者，我希望只需遵循应用的接入要求，并自行管理反向代理，以便此次工作不接管现有基础设施。
39. 作为部署者，我希望容器仍可启动服务并接受存活检查，以便移除客户端不破坏部署。
40. 作为维护者，我希望移除一次性发送、交互式 CLI 及其文档和专属测试，以便不维护没有实际使用场景的入口。
41. 作为维护者，我希望保留 Web 依赖的 HTTP 业务契约和服务生命周期测试，以便删客户端不误删服务能力。
42. 作为维护者，我希望用 HTTP 行为和真实浏览器流程验证登录，以便不靠检查源代码字符串猜测安全性和可用性。
43. 作为维护者，我希望文档明确当前实现与后续规划，以便检索、幂等及删除能力不会被误报为本次已经实现。

## Implementation Decisions

### 1. 交付边界与领域约束

- 本次交付为 Web 安全登录、认证迁移、CLI 客户端移除及相关文档与测试；不是整个 README 限制清单的合并改造。
- 保持单用户模型；多设备指同一使用者在不同浏览器持有独立登录会话，不引入账号注册、角色、租户或分用户记忆库。
- 登录会话是可撤销的访问资格，不是记忆条目，没有证据资格；对话上下文仍不保存或自动续接。
- 记忆 JSONL 格式不变，只有模型判定为记录的输入才形成记忆条目；原文、记录时间、版本及引用语义保持不变。
- 独立持久化必要的认证状态是明确获准的例外，不允许借此持久化查询、回答、模型原始响应或原文审计档案。

### 2. 凭据与配置

- 正常运行仅提供单用户密码登录；不设用户名，也不提供公开的“首位访问者初始化密码”流程。
- 部署者提供使用成熟自适应密码哈希算法生成的编码结果；不得自制密码算法、以普通摘要代替密码哈希，或把明文密码当成配置中的哈希接受。具体算法与依赖由实施选择并记录。
- 提供可复制、不会将密码或哈希写入应用日志的初始化与密码恢复指引；生成哈希的管理步骤不等于恢复被移除的记忆 CLI 客户端。
- 登录密码、模型 API key、会话凭据不得复用。启动时校验哈希格式及必要认证配置；缺失、空白、无效均报错退出。
- 只通过显式开发配置允许匿名模式，默认关闭；不得从是否存在旧 token、是否缺失密码或请求来自何处推断开发模式。
- 识别旧鉴权配置并给出迁移错误；仍设置旧默认 Bearer 环境变量的部署也应收到明确迁移提示，不允许静默继续使用旧认证方式。错误文本不得回显凭据值。
- 旧 Bearer token 不再授予任何访问资格。配置名称、路由命名等具体接口在实施时统一确定，文档、示例及测试必须一致。

### 3. 登录会话生命周期

- 使用高熵不透明浏览器凭据及可撤销的服务端登录会话状态；成功登录创建新的访问资格，不能沿用未认证浏览器提供的会话标识。
- 浏览器通过 Cookie 携带登录凭据，正常 HTTPS 模式设置 HttpOnly、Secure、适当的 SameSite 与最小必要作用域，不使用 localStorage 或 sessionStorage 保存凭据。
- 连续 7 天无有效使用即过期；每次登录最长有效 30 天。有效使用可推进闲置期限，但不得推进绝对期限；后台轮询和存活检查不能让闲置设备永不过期。
- 正常重启使用同一认证状态及凭据配置时，有效登录会话保持；过期及已撤销状态不能因重启重新变得有效。
- 状态丢失、损坏或无法安全读取时不得回退匿名授权；可以要求重新登录或明确拒绝启动，具体故障行为必须确定并测试。
- 退出当前设备只撤销当前登录会话，并清除浏览器凭据。退出所有设备必须重新验证密码，撤销包含当前设备在内的全部登录会话，并清除当前凭据。
- 替换密码哈希并重启必须使旧登录会话失效；即使操作者仅重新生成了同一密码的不同哈希，也按凭据配置变更保守失效。认证状态恢复说明不得把回滚旧状态作为“恢复被撤销会话”的正常办法。
- 会话及撤销状态的持久化应避免只在内存撤销后对外报告成功；不得存放在记忆分片内或进入记忆检索。

### 4. HTTP 安全行为

- 提供登录、会话状态检查、退出当前设备、重新验证密码后退出所有设备的 HTTP 行为；具体端点名称由实施确定，状态变更不得使用 GET。
- 记忆业务在解析、分类、检索和写入之前校验有效登录会话；缺失、过期、撤销或伪造凭据返回一致的未认证响应，不执行模型调用或产生记忆写入。
- 错误密码不建立登录会话，错误响应不泄露密码验证内部细节。登录及再次验证密码的入口有有界、可测试的尝试限制，限速不得造成永久账号锁定；不盲信客户端伪造的转发地址来划分限速身份。
- Cookie 认证的状态变更入口必须防 CSRF，包括登录、注销和记忆提交；SameSite 不能作为唯一防护。结合明确的来源验证与适当的 CSRF 校验，不能因缺少某个头或客户端使用非 JSON Content-Type 而绕过。
- 明确客户端与应用之间的来源契约，不从任意 Host 或转发头推导可信来源。任何代理信任能力必须显式限定；不要求本次修改用户反向代理。
- 登录页面与必要静态资源可以公开，但不得嵌入私人原文、回答或凭据。存活检查保持不鉴权，只提供最小状态，不泄露配置和模型密钥。
- 认证响应、私人业务响应不得进入共享缓存；登录密码或会话凭据不能放在 URL 中，也不得记录请求体、Cookie 或敏感认证头。
- 继续安全渲染原文、回答和引用，不以新增登录 UI 为由引入不安全的 HTML 拼接或第三方脚本。

### 5. Web 交互

- 页面可区分尚未登录、已登录、认证过期及暂时服务错误；HTTP API 的认证错误不得被当成模型错误展示。
- 未成功提交的原文仅在当前页面内存中保留，包括登录过期及模型失败；重新登录后由用户主动确认再次提交，不能自动重放。
- 主动退出时清除当前页面展示的私人原文、回答、引用及草稿；会话失效后不再保留可继续操作的旧私人视图。认证过期时允许保留未提交草稿供原使用者重新登录，不写浏览器持久化存储。
- 跨标签页的显示不得被误认为独立身份；使用同一 Cookie 的标签页属于同一登录会话。退出后其他标签页不能继续成功调用业务，页面恢复或再次交互时应检查认证状态并清理失效视图。
- 查询、回答及对话上下文不持久化；刷新页面不恢复聊天历史。浏览器持久化登录 Cookie 不属于聊天历史。

### 6. 与模型可用性解耦

- 登录、会话检查、注销、服务端撤销及存活检查不调用外部模型，也不以模型连通性作为可用条件。
- 分类与回答维持模型失败时明确报错的行为，不绕过分类自动保存、不后台排队，也不添加离线回答。
- 模型故障不等于整个进程死亡；文档及状态展示区分进程存活、认证可用和模型业务可用。

### 7. CLI 移除与兼容边界

- 移除一次性发送、交互式会话、客户端服务器地址参数、客户端 Bearer token 读取和终端业务响应格式化，以及对应专属文档和测试。
- 保留服务可执行入口、配置加载和校验、监听、信号处理及优雅退出；保留 `shiyi serve` 的部署启动兼容性。帮助与版本等必要服务管理能力不算面向使用者的记忆客户端。
- 不删除 Web 依赖的 `POST /messages`、存活检查、Web 静态资源、服务端请求/响应契约和分类/记录/查询链路。
- 已移除的客户端调用应明确失败或给出新的服务用法，不得静默启动交互式客户端或误当服务操作。
- 更新容器、冒烟、配置示例、文档一致性检查及相关 CI 流程，使默认安全模式可启动且认证测试真实覆盖；不得仅为了通过原有测试而放宽生产鉴权默认。

### 8. 隐私与部署责任

- 当前版本允许敏感原文保存，也允许发送给部署者配置的模型网关及其上游模型；不实现隐私字段、脱敏替换或仅本地模式，不宣传自定义网关等于数据完全不外发。
- 信任运行中的服务器及管理员。不承诺服务器被完全攻陷时仍保密，不承诺模型提供方无法读取发送给它的原文。
- 保持明文 JSONL，不新增应用层或客户端端到端加密。文档明确必要的数据目录权限、避免静态发布数据、加密备份及分离保管解密密钥；离线磁盘保护交由宿主机加密。
- 限制新增认证状态文件的访问权限；不把敏感目录改成全员可写，不建议以长期 root 运行代替正确权限。
- 反向代理、证书、域名和网络配置由用户负责，本次不检查或修改实际部署。应用需说明 HTTPS、来源配置和防绕过接入要求，但不能声称这些部署措施已经执行。
- 如记录必要安全事件，只记录事件种类、时间等非原文信息，禁止凭据和记忆业务正文；不引入查询/回答审计档案，也不扩展成登录审计产品。

## Testing Decisions

### 已确认的接缝

以应用 HTTP 入口为主要自动化接缝，沿用当前测试对分类、记录、回答依赖的可控替身与临时目录，避免给认证内部各个函数分别建立模拟接口。少量真实浏览器与服务进程/容器冒烟验证 HTTP 单独无法证明的行为；不引入真实外部模型作为测试前置条件。

### 好测试的标准

测试可观察的授权结果、响应、Cookie、记录是否形成、重启后状态及浏览器交互，不锁定私有函数、存储序列化细节或组件调用顺序。未认证时“没有模型调用、没有记录写入”属于关键外部副作用边界，可以使用现有替身验证；不得把实现细节数量当安全保证。

### 必须覆盖的行为

1. 未登录时业务操作拒绝；登录页面和最小存活检查可访问；错误密码、空密码及伪造/旧 Bearer token 均不授予访问资格。
2. 正确登录创建受保护 Cookie，经过 HTTP 入口可完成原文记录与查询引用；原文不被登录层改写，查询和回答不持久化。
3. 两个独立浏览器 Cookie jar 可分别使用；退出其一不影响另一个；退出所有设备需正确的再次验证密码，并使所有旧 Cookie 被拒绝。
4. 通过可控时间验证闲置 7 天及绝对 30 天边界、期限前后行为、有效使用与非使用的区别；不使用实际长时间等待或脆弱 sleep。
5. 以同一临时认证目录重新构造或重启服务，验证正常重启保留有效登录、注销不会复活、密码哈希更换后旧登录被拒绝；状态损坏或丢失不能匿名放行。
6. 跨站登录、跨站提交、跨站注销、错误/缺失的防伪信息以及欺骗性来源和转发头均不能绕过保护；验证同源合法操作正常工作。
7. 登录与再次验证密码的限速可触发并恢复，不产生永久锁定；测试采用可控时间，不依赖真实公网地址。
8. 模型替身持续超时或报错时认证和注销仍可工作，业务操作明确失败；不得产生未分类记录。
9. 在专用测试输入中放入可辨认的密码、会话凭据、模型密钥及原文标记，验证错误输出和日志不含这些值；不读取真实部署凭据。
10. 真实浏览器使用测试用 HTTPS 环境验证 Cookie 的实际接收与发送、登录页到业务页、认证过期后保留草稿且不自动重发、主动退出清屏与返回页面的失效处理。不以源码含有某个字符串代替浏览器验收。
11. 配置缺失/无效、旧 Bearer 配置、显式开发匿名模式各自行为正确；普通模式不能因漏配自动匿名运行。
12. 服务启动、停止和容器探活仍通过；旧用户 CLI 不再可用，Web 使用的 HTTP 接口仍可用。
13. 文档检查覆盖新入口、迁移说明和真实边界，移除强制要求旧 CLI 存在的断言，但保留原文、引用、冻结测试集和不持久化查询/回答的保护。

### 既有测试参考与门禁

复用当前 HTTP 集成测试中的“鉴权失败不分类/不写入”、存活检查和错误映射案例，保留现有 Web 安全文本渲染测试、查询不落盘验收和服务启停测试。现有 Web 源码字符串检查可辅助静态约束，但不能充当新增登录流程的完整验收；冻结测试集保持不可就地修改，按现有版本化约定扩展。

实施完成必须运行唯一的本地门禁 `make check`；涉及容器的认证配置和启动路径必须通过 `make image-check`。新浏览器验收应有可重复的执行入口并纳入明确的验证流程，报告其执行结果与环境前提，不得把未运行标为通过。

## Out of Scope

- 多用户、注册、用户名、角色权限、家庭共享、第三方身份服务、邮箱/短信恢复、MFA、设备管理列表。
- 长期 API token 管理、每设备 token、新 CLI 客户端或让脚本模拟网页登录的产品支持。
- 用户反向代理、证书、域名、防火墙和实际部署服务的操作。
- 原文脱敏、隐私等级字段、仅本地记录模式、客户端端到端加密、应用层数据加密以及替用户部署磁盘/备份加密。
- 查询与回答历史、对话上下文、附件、OCR、向量检索、异步队列和离线问答。
- 记忆条目的查看管理页、删除、更正、替代记录和备份中的遗忘语义。
- 本次直接实现跨换行检索修复、提交幂等或回答逐项证据校验；这些为独立后续交付，不混入本次验收。
- 对语义召回完整性、模型零幻觉或服务器完全失陷后保密作绝对保证。

### 领域文档与历史追踪

- [ADR 0001](<../../docs/adr/0001-jsonl-as-sole-source-of-truth.md>)：记忆 JSONL 仍是唯一记忆真相源，记录不可改写。
- [ADR 0003](<../../docs/adr/0003-contradictory-memories-coexist.md>)：矛盾记忆并列，不由模型裁决或自动覆盖。
- [ADR 0006](<../../docs/adr/0006-only-records-are-persisted.md>) 由新增的 [ADR 0007](<../../docs/adr/0007-authentication-state-is-not-memory.md>) 限定认证状态例外；不是许可保存聊天历史。
- [ADR 0005](<../../docs/adr/0005-service-availability-follows-model.md>) 由新增的 [ADR 0008](<../../docs/adr/0008-model-availability-does-not-gate-authentication.md>) 明确模型业务与认证可用性的区别。

### 后续独立交付的已定方向

以下是需求讨论中已确定的方向，不是本规格的附加验收清单，也不将尚未细化的事项标成已实现：

1. **检索正确性**：JSONL 每个物理行一条记录，原文内部换行被 JSON 转义，两者不能混淆。原文不改写，检索增加空白归一化，修复 JSON 编码预筛与解码原文匹配不一致；预筛不得排除符合规则的记录，无法安全预筛时回退解码扫描，不跨记忆条目拼接，返回原文引用。保证仅指符合约定匹配规则的记录不被实现错误漏掉，不保证同义表达和模型关键词的绝对召回。当前对含真实换行关键词可能触发 ripgrep 错误的判断来自静态核查，实施前须补回归验证，不能称为已经实测修复。
2. **提交幂等**：同一次提交的网络重试只能形成一条记忆条目；主动再次提交相同原文仍允许产生新记录，不做原文全局去重。需要独立规格定义请求身份、保存范围及期限，并显式修订旧 ADR 中放弃幂等的部分；不能为幂等顺带保存查询与回答档案。
3. **回答可靠性**：关于使用者的事实应能对应原文，依据不足时省略或明确不确定，冲突不擅自裁决，优先可核对引用；不能把引用存在性校验宣传为逐句正确或没有幻觉。独立规格与验收集确定可执行标准。
4. **记忆生命周期**：查看、删除和用新记录替代旧记录后续另行讨论，必须一并决定备份残留、历史引用和矛盾记忆语义；目前仍保持追加式记录，不因本次登录而更改现有 ADR。

建议实施次序：先完成本规格的登录与客户端移除，再分别整理检索、幂等、回答可靠性的规格与任务；本次只发布当前核心规格，不预先扩张后续交付。
