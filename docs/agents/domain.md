# Domain Docs

规定工程技能探索本项目时如何读取领域文档。

## 布局

采用 single-context：

- 根目录 `GLOSSARY.md`：项目领域词汇。
- `docs/adr/`：架构决策记录。

## 探索前读取

- 读取根目录的 `GLOSSARY.md`。
- 读取 `docs/adr/` 中与当前工作范围相关的 ADR。

文件或目录不存在时，静默继续；不把缺失视为问题，也不预先建议补建。
由 `/domain-modeling` 在术语或决策明确后按需创建。

## 使用词汇表中的术语

在任务标题、重构建议、假设、测试名称等输出中命名领域概念时，
使用 `GLOSSARY.md` 定义的术语，避免换成词汇表明确排除的同义词。

所需概念尚未收录时，先检查是否引入了项目不用的说法；
确有词汇缺口时，记录下来供 `/domain-modeling` 处理。

## 显式指出 ADR 冲突

建议与既有 ADR 冲突时，明确指出对应 ADR 和重新讨论的理由，
保留现有决策的可追溯性。
